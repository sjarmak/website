05 / Temporal Workflow
podcast_workflow.py · excerptDeterministic orchestration
@workflow.defn
class PodcastResearchWorkflow:
    @workflow.query
    def progress(self) -> PodcastProgress:
        return self._progress

    @workflow.run
    async def run(self, pipeline: PodcastPipelineInput):
        for offset in range(
            0, total, pipeline.max_parallel_episodes
        ):
            batch = pipeline.episodes[
                offset : offset + pipeline.max_parallel_episodes
            ]
            results = await asyncio.gather(
                *(self._run_episode(...)
                  for episode in batch)
            )
        series_reviews = await asyncio.gather(
            *(self._write_series_review(...)
              for series in pipeline.series)
        )
Owns

Episode order, bounded concurrency, progress, completion policy, and final fan-in.

Excludes

Network calls, model calls, file I/O, clock reads, and environment access.

Persists

Temporal records the decisions in Event History so another Worker can replay them.

07 / resilience and tradeoffs

Retries need an application contract

RetryThree attempts with bounded exponential backoff.
TimeoutStage-specific Start-to-Close limits.
HeartbeatThirty seconds for long external calls.
IdentityStable request IDs and artifact paths.

Temporal provides at-least-once Activity execution. The response journal suppresses repeated reads after a response is stored. A paid or mutating provider must also honor the request ID to cover the gap between provider success and the journal write.

Large evidence stays in artifact storage; Event History carries compact references
