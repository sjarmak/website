# Code Retrieval & Enterprise Codebases — Literature Review

## Scope & method

This review surveys the literature on retrieving code from large, real-world software systems: how it differs from text information retrieval, the technique ladder that has grown to address those differences, the move from single-file to repository scale, the distinct pressures that emerge inside enterprise codebases, and the open frontier. It draws on three source layers. The first is the SciX/NASA-ADS corpus (the arXiv mirror), accessed through the SciX MCP server; every claim grounded in a corpus paper carries an ADS bibcode (e.g. `2019arXiv190909436H`). The second is industrial systems documentation — Google, Meta, and Sourcegraph engineering writeups — which is the *primary* evidence for production code search because the peer-reviewed literature largely does not operate at billions-of-lines scale; these are cited by title and URL. The third is a set of local benchmark projects (`EnterpriseBench`, `CodeScaleBench`, `codeprobe`) that encode enterprise-specific challenges the public benchmarks miss.

Two corpus gaps shape what can and cannot be said with confidence. First, the dense/ANN vector index was unavailable during source gathering, so corpus recall here is lexical/hybrid only; absent classics include pre-arXiv lexical/structural code search (Sourcerer, Portfolio, Exemplar) and origin work on code property graphs (Yamaguchi/Joern). Second, several named systems — RepoGraph (Ouyang et al., ICLR 2025), GRACE (Wang et al., arXiv:2509.05980), the published EnterpriseBench (arXiv:2510.27287) — are referenced by external id but not resolved to bibcodes; they are cited as such and **no bibcode is fabricated for them**. Access-control-aware retrieval is the thinnest academic sub-topic of all; here the field leans almost entirely on industry.

## Landscape

### Why code isn't text IR

The founding observation is that code retrieval is not text IR with a different corpus. Text IR assumes meaning lives in shared vocabulary between query and document; code violates that assumption in both directions. A developer's intent ("acquire a lock with a timeout") and the implementation (`tryAcquire(50, MILLISECONDS)`) share almost no tokens — the gap that CodeSearchNet was explicitly built around ([Husain 2019, `2019arXiv190909436H`]). And code has a runaway vocabulary of its own: Karampatsis et al.'s "Big Code != Big Vocabulary" showed identifier names proliferate without bound, so out-of-vocabulary issues "severely affect Neural Language Models of source code… rendering them unable to scale" ([`2020arXiv200307914K`]). Lexical search owns rare exact identifiers (`OAuth2TokenValidator`) but drowns in noise on common terms; embeddings cover the synonym gap but smear rare tokens into plausible-but-wrong neighborhoods. Neither wins alone, which is why every serious system is hybrid — "mgrep finds the file, grep finds the line" (Sourcegraph, "Semantic Code Search").

Structure is the signal text IR throws away. MISIM argued existing methods "mainly operate on identifiers" while "control and data flow are not exploited explicitly," and lifted similarity scoring onto a context-aware semantics structure ([Ye 2020, `2020arXiv200605265Y`]); GraphCodeBERT pretrained on data flow rather than the token sequence ([Guo 2020, `2020arXiv200908366G`]). Even the metrics can't be borrowed: BLEU and exact-match punish semantically equivalent programs, so CodeBLEU injects AST syntax and data-flow semantics back in ([Ren 2020, `2020arXiv200910297R`]) — the same two structural signals that make retrieval work also make measurement work. The intent→query→code chain is lossy enough that an entire subfield exists just to rewrite developer queries ([Masudur Rahman 2021, `2021arXiv210809646M`]). The evaluation backbone matured from CodeSearchNet to CoIR ([Li 2024, `2024arXiv240702883L`]) and CoSQA+ on real developer search logs ([Gong 2024, `2024arXiv240611589G`]); two surveys map the terrain ([Di Grazia 2022, `2022arXiv220402765D`]; [Zhang 2023, `2023arXiv231107989Z`]).

### Techniques: lexical → neural → graph

The technique ladder is additive, not a sequence of replacements — each rung covers the prior rung's blind spot. **Rung 1, lexical/trigram/BM25**, remains the production first stage: fast, exact, interpretable, unbeatable on rare tokens. The cautionary result is CodeMatcher, a lexical method modeling the sequential semantics of query words that rivaled early neural code search ([Liu 2020, `2020arXiv200514373L`]). **Rung 2, neural embeddings**, fixes the synonym gap: CodeBERT established the bimodal encoder ([`2020arXiv200208155F`]), and the contrastive lineage sharpened it — ContraCode ([`2020arXiv200704973J`]) and CoCoSoDa's soft augmentation plus momentum-queue negatives ([`2022arXiv220403293S`]), with RocketQA supplying the dual-encoder training recipe ([`2020arXiv201008191Q`]) and Neelakantan showing large-scale contrastive pretraining transfers to code ([`2022arXiv220110005N`]). The standing successors are UniXcoder ([`2022arXiv220303850G`]) and CodeT5 ([`2021arXiv210900859W`]). **Rung 3, AST/graph**, recovers behavior: GraphCodeBERT's data-flow injection, deGraphCS's variable-flow graph ([`2021arXiv210313020Z`]), GraphSearchNet's GNN dependency capture ([`2021arXiv211102671L`]), Deep Graph Matching reframing retrieval as graph matching ([`2020arXiv201012908L`]), and heterogeneous typed program graphs ([`2020arXiv201204188Z`]). **Rung 4, hybrid retrieve-then-rerank** (Lin et al., [`2020arXiv201006467L`]), spends precision only on a shortlist: ColBERT's late-interaction middle ground ([`2020arXiv200412832K`]), Cascaded Fast & Slow ([`2021arXiv211007811G`]), and CoRNStack's contrastive data ([`2024arXiv240201007S`]).

The sharpest dissent is whether dense actually beats lexical. Contriever showed an unsupervised dense retriever *loses* to plain BM25 absent supervision ([Izacard et al., `2021arXiv211209118I`]) — direct ammunition for "never retire lexical." The practical pipeline that falls out of this is the industrial pattern: `BM25 top-20 + vector top-20 → Reciprocal Rank Fusion → cross-encoder rerank → top 5–10`, fusing on ranks because BM25 and cosine scores live on incomparable scales ("Building Hybrid Search That Actually Works," ranjankumar.in).

### Repository scale & code graphs

A file is a unit you can read; a repository is a world you must navigate. A field study of 7,012 Claude Code sessions found agent exploration so undirected that handing over a formal architecture descriptor cut navigation steps 33–44% (d=0.92) and slashed behavioral variance 52% ([Jin 2026, `2026arXiv260413108J`]). The field splits into three camps. **Similarity, iterated:** RepoCoder's retrieve-generate-retrieve loop ([`2023arXiv230312570Z`]), bridged toward structure by DraCo's dataflow-guided context graph (+3.43% EM, +3.27% identifier-F1, [`2024arXiv240519782C`]). **Query a structured world model:** CodexGraph indexes the repo into a graph database the LLM queries directly ([`2024arXiv240803910L`]); CodeGRAG trains a GNN structural expert ([`2024arXiv240502355D`]); QVoG proves a compressed code property graph traverses 1M+ LOC in ~15 min ([`2024arXiv240608098L`]); the Code Digital Twin fuses extractable and tacit knowledge ([`2025arXiv250307967P`]); AOCI builds a symbolic-semantic blueprint read in a single pass ([`2026arXiv260502421L`]). **Agentic navigation:** SWE-agent's agent-computer interface (and the sobering finding that iterative search can *degrade* performance, [`2024arXiv240515793Y`]); OpenHands ([`2024arXiv240716741W`]); MAGIS's dedicated "Repository Custodian" localization agent ([`2024arXiv240317927T`]); LocAgent's multi-hop graph reasoning (92.7% file-level localization, +12% issue resolution, [`2025arXiv250309089C`]); CodePlan's dependency-graph planning ([`2023arXiv230912499B`]); ARISE ([`2026arXiv260503117S`]). The retrieval-scope taxonomy — local/global/third-party — comes from A³-CodGen ([`2023arXiv231205772L`]), and the moving external surface from LibEvolutionEval ([`2024arXiv241204478K`]). Benchmarks: RepoBench ([`2023arXiv230603091L`]) and CrossCodeEval ([`2023arXiv231011248D`]). The industrial ancestors are build-integrated indexers — Kythe, Glean, SCIP.

### Enterprise codebase challenges

Scale does not just make existing problems bigger — it changes which problems exist. Google's tree holds ~2B LOC across 9M files absorbing ~40K commits/day from 10,000+ engineers (Potvin & Levenberg, CACM 2016). Seven pressure points emerge: sheer size, polyglot cross-language dependency chains, access-control boundaries, stale/dead code and churn, tribal knowledge, build-system complexity, and honest evaluation. The industrial answer is a built index in distinct, routinely-conflated layers: Zoekt trigram *text* search (sub-50ms regex over ~2 GB at ~1.2× corpus size in RAM); Kythe build-integrated *semantic* cross-references; Glean's incremental indexing (the architectural answer to churn — reindex the diff, not the world); and Sourcegraph SCIP for compiler-accurate cross-repo navigation.

The context problem is not solved by long windows: MutaGReP's execution-free plan search rivals full-repo GPT-4o using <5% of a 128K window ([`2025arXiv250215872K`]), and RepoQA shows capacity ≠ comprehension — models even understand code *better* with distracting comments removed ([`2024arXiv240606025L`]). Polyglot defects hide at the language boundary: K-Trans's ablation found dependency-usage examples contribute most (+19.4%/40.2% pass@1, [`2025arXiv250318305O`]); SWE-bench-java exposed how language-specific "agentic SE" capability was ([`2024arXiv240814354Z`]). Clone/stale debt needs disk-based similarity at scale ([Chochlov 2023, `2023arXiv230902182C`]; [Aftab Ahmed 2025, `2025arXiv250417972A`]). And the most under-modeled reality: decisions live outside the source. Augmenting an agent with product context lifted decision compliance from 46% to 95% — scoring 100% on codebase-visible decisions but 0–33% on product-context ones without it ([Dillon 2026, `2026arXiv260508112D`]). The in-source half is handled by repo-completion work like R2C2-Coder ([`2024arXiv240601359D`]); the tribal half needs a separate substrate.

### Frontier & open problems

Model capability outran the plumbing, so the marginal win is now retrieval quality. The sharpest new finding is that **retrieval can hurt**: under hidden commit freshness, stale-only retrieval induced obsolete-API references in 15/17 (Qwen2.5-Coder-7B) and 13/17 (gpt-4.1-mini) samples — +88.2/+76.5 pp over current-only, while no-retrieval produced zero stale refs ([Weng 2026, `2026arXiv260514478W`]). DocSync names the failure taxonomy ("Silent Constraint Shifts," "Tutorial Rot," [`2026arXiv260502163B`]). The strongest new corpus cluster is graph-guided localization: KGCompass reached 45.67% on SWE-bench-Lite at $0.20/repair, with **69.7% of correctly localized bugs requiring multi-hop KG traversal** — a clean quantitative argument that flat similarity structurally misses most real bug sites ([`2025arXiv250321710Y`]); GALA extends graph alignment to GUI-bug screenshots ([`2026arXiv260408089L`]). Permission-aware retrieval is the academic gap; the human-side demand is "bounded delegation" with least-privilege scoping ([Choudhuri 2026, `2026arXiv260407830C`]), and enforcement leans on industry (PermLLM, arXiv:2505.22860; access control for LLM agents, arXiv:2510.11108). Polyglot retrieval is mapped by the Multilingual Code Intelligence survey ([`2026arXiv260425960J`]) and the Breaking-Changes SLR ([`2026arXiv260524397C`]).

## Cross-cutting themes

**Hybrid is structural, not an optimization.** From Episode 1's two-sided failure to Episode 2's additive ladder to Episode 4's layered industrial index, the same conclusion recurs: exact match for symbols, semantic for intent, structure for behavior. The dissent (Contriever, [`2021arXiv211209118I`]; CodeMatcher, [`2020arXiv200514373L`]) is over *mix*, not over *whether to mix*.

**Structure beats tokens — with an operational asterisk.** Data-flow and graph signals (GraphCodeBERT, MISIM, DraCo, QVoG, KGCompass) consistently beat token-bag baselines on behavior and localization. But they require a working parser, a build step, and index maintenance — costs that are real in a polyglot enterprise repo with partial files, where trigram/BM25 degrade gracefully on garbage and graphs do not.

**Capacity is not comprehension.** Long-context windows do not dissolve retrieval (MutaGReP, RepoQA); a small grounded plan beats a full-repo dump, and more text in context can actively distract.

**More search can be a tax.** SWE-agent's degradation finding, the 12-turn efficiency threshold, and Jin's navigation-step reduction all say undirected exploration is a cost — front-load a map.

**The half of the truth not in the source.** The 49-point product-context swing ([`2026arXiv260508112D`]) and the Code Digital Twin's tacit-knowledge thesis ([`2025arXiv250307967P`]) say the highest-value context is precisely what static analysis cannot extract.

**Evaluation is contaminated and tool-causality is unmeasured.** Riddell quantifies benchmark↔pretraining overlap ([`2024arXiv240304811R`]); the local trio (`EnterpriseBench`, `CodeScaleBench`, `codeprobe`) treats tool access as a controlled variable, reports the honest modest lift (Haiku-4.5 mean reward 0.536 baseline → 0.565 MCP), and defeats the ground-truth tautology with multi-source consensus (≥2 of Sourcegraph/AST-oracle/grep). The published EnterpriseBench (arXiv:2510.27287) reports SOTA ~21.5% — agents fail four of five enterprise tasks.

## Open problems & the frontier

The brainstorm report ranks twelve open problems; the corpus has sharpest evidence on a subset. (1) **Retrieval under access-control boundaries** — thinnest sub-topic, industry-only enforcement, "bounded delegation" the design language. (2) **Contamination-proof eval from private history** — Riddell's overlap quantification justifies `codeprobe`. (3) **Symbolic+semantic hybrid index at monorepo scale** — AOCI and QVoG anchor it; nobody ships the *fused, always-fresh* index, the unclaimed prize. (4) **Staleness-aware retrieval** — Weng's "retrieval hurts" diagnostic argues for gating on temporal validity, not just relevance. (5) **Polyglot dependency-aware retrieval** — dependency context, not function bodies, carries the hard-to-retrieve signal. (6) **Tribal-knowledge retrieval** — measurably changes behavior (+49%). (7) **Build-graph-grounded context selection.** (8) **Tool-vs-no-tool causal evaluation** — still no clean isolation of "did the tool help or did the model already know." (9) **Long-context vs retrieval policy** — open question of *when* retrieval still beats a dump. (10) **Incremental real-time index maintenance** — O(changes) not O(repository); held by industry (Glean). (11) **Graph-guided edit localization** — KGCompass's 69.7% multi-hop result. (12) **Cost-latency-bounded retrieval at scale.** The synthesizing bet: the first system to ship a fused symbolic+semantic index that stays fresh under O(changes) updates, respects access boundaries, and gates on freshness wins the frontier.

## How this connects to agent memory

Code retrieval is the *read path* of a codebase memory. An agent's working memory of a system it cannot hold in context is reconstructed, on demand, by retrieval — so every pathology of memory has a retrieval analogue here. **Staleness is forgetting's inverse failure: false remembering.** Weng's result ([`2026arXiv260514478W`]) shows a memory that confidently returns dead state is worse than one that returns nothing — the dangerous failure is not a missed retrieval but a confident retrieval of obsolete or unauthorized state. A codebase memory therefore needs the equivalent of recency-weighted decay: carry commit timestamps and version pins into the index and *decline* stale entries, exactly the freshness-gating the frontier demands. The O(changes) incremental-indexing reframe (Glean) is memory consolidation — write only the delta, keep the store live rather than rebuilding from scratch.

**Salience is the localization problem.** KGCompass's finding that 69.7% of bug sites require multi-hop graph traversal ([`2025arXiv250321710Y`]) is a statement about what a good memory must surface: the relevant item is rarely lexically near the cue. Flat similarity retrieval is associative recall by surface features; graph traversal is structured recall along the relations that actually carry meaning (calls, imports, dataflow). Jin's "give the agent a map first" ([`2026arXiv260413108J`]) is the schema-before-episodes principle — a structural prior that makes retrieval directed rather than a tax. **Tribal knowledge is the boundary of an extractive memory**: the +49% product-context swing ([`2026arXiv260508112D`]) and the Code Digital Twin's tacit knowledge ([`2025arXiv250307967P`]) say the most salient context lives outside the artifact being indexed, demanding a separate memory store fused at read time. And access-control ([`2026arXiv260407830C`]) makes memory *scoped*: what an agent is allowed to remember about a system is a per-principal least-privilege question, not a global index. The through-line: retrieval quality, not model capability, is now the binding constraint — which is precisely the claim agent-memory research makes about the read path of any long-lived agent.
