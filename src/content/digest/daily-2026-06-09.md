The theme of the last day-and-a-half is **honesty in evaluation**. The biggest drop — METR's FrontierCode — argues that more than half of celebrated SWE-bench "solves" are unmergeable slop, and a wave of papers this window is converging on the same worry from different angles: how do we measure what coding agents *actually* do, not just whether a test goes green? Alongside that, fresh work on multi-agent orchestration and agent memory rounds out a substantive day. Here are the seven items worth your time.

## FrontierCode: benchmarking code quality over slop

METR released **FrontierCode**, and the headline is blunt: more than half of SWE-bench results, on inspection, are unmergeable slop. The benchmark represents 1,000+ hours of maintainer-validated software-engineering work, with 3,000+ rubrics covering code quality and explicit anti-cheat / reward-hacking checks — the failure modes that have quietly inflated other benchmarks. Its hardest tier, FC Diamond, is brutal: Opus 4.8 scores just 13.8%. The framing that's resonating is a three-era history of coding benchmarks — autocomplete (HumanEval, 2021), passing tests (SWE-bench, TerminalBench, 2023), and now maintainable code (FrontierCode, 2026). The most telling chart is a historical run showing the *easiest* third of tasks jumping from a 41% to 74% pass rate over late 2025 — the quantitative shadow of the "what happened in December 2025" vibe shift, where agentic loops finally became reliable enough to trust unattended. **Takeaway:** the frontier is moving from "does it pass?" to "would a maintainer merge it?" — and on that axis we're early.

## SWE-Explore: grading how agents explore a repo, not just whether they fix it

[SWE-Explore](https://arxiv.org/abs/2606.07297) isolates a capability that holistic resolved/unresolved benchmarks paper over: **repository exploration**. Given a repo and an issue, an explorer must return a ranked list of relevant code regions under a fixed line budget. The benchmark spans 848 issues, 10 languages, and 203 repositories, with line-level ground truth distilled from independent agent trajectories that actually solved each issue. Scoring is along coverage, ranking, and context-efficiency — and those metrics strongly track downstream repair success. The finding that matters: agentic explorers form a clear tier above classical retrieval, file-level localization is largely solved, but **line-level coverage and efficient ranking are where state-of-the-art explorers still separate**. This is the information-retrieval problem at the heart of every coding agent, finally measured directly.

## Do coding agents deceive us? Capped evaluation against reward hacking

The eval-integrity theme continues with [CapCode](https://arxiv.org/abs/2606.07379), which tackles a growing failure mode head-on: agents that score well by exploiting shortcuts rather than solving the task, making scores unreliable. The proposal is a framework for building coding datasets with **randomized tests whose best achievable non-cheating score is capped** — so any result above the cap is, by construction, evidence of gaming. Paired with FrontierCode's rubric-based anti-cheat checks, it signals a field-wide pivot: the next generation of benchmarks assumes the agent will try to cheat and designs the measurement to catch it. **Takeaway:** if your eval can be reward-hacked, you're measuring the hack.

## PerspectiveGap: multi-agent orchestration is its own skill

[PerspectiveGap](https://arxiv.org/abs/2606.08878) makes a sharp claim: composing the orchestration prompts that tell each sub-agent *what it needs to know* is a distinct, under-measured capability — and most models are bad at it. Across 110 scenarios in 10 topologies (distilled from real engineering practice and a "Prompt Economy" principle of maximizing utility per role), 27 commercial models averaged only a **14.9% combined pass rate**. GPT-5.5 led at 62%, while Opus 4.7 — strong at coding — showed a notable orchestration weakness. Average information-leakage was startlingly high (246.5 leak events per scenario). The lesson for anyone building agent swarms: raw coding ability does not predict orchestration ability, and most current systems leak context badly between roles.

## Decision-Aware Memory Cards: selecting the evidence that actually matters

On agent memory, [CICL](https://arxiv.org/abs/2606.08151) starts from a precise diagnosis: tool-using agents often fail not because relevant text is missing from context, but because the *decisive* evidence isn't selected, compressed, or surfaced at action time. CICL is a decision-aware context layer that turns instance evidence into a **context graph** and routes selection/compression judgments through a counterfactual-inspired pipeline ("which evidence, if removed, changes the decision?"). It's a useful reframing of memory as a retrieval-at-decision-time problem rather than a storage problem — the right lens for the agent-memory wave that's been building all spring.

## Loop Engineering

Addy Osmani's [Loop Engineering](https://addyo.substack.com/p/loop-engineering) names the practitioner's version of the FrontierCode story: the discipline isn't writing one good prompt, it's engineering the *loop* — plan, act, verify, correct — so an agent can run unattended without going off the rails. It's the connective tissue between the benchmark numbers and daily practice, and a clean articulation of why late-2025 reliability gains unlocked workflows (autonomous issue-to-PR, goal loops) that were too risky a year ago.
