Point an open-source coding agent at a task with a dependency it has to interpret, and it gets that interpretation wrong in up to 98.5% of cases. That number comes from [SWE-MISBEHAVIOR](https://arxiv.org/abs/2610.18206), a 7.4K-sample taxonomy from Do Xuan Trong, Shafiq Joty, Min-Yen Kan and colleagues that stops asking whether a coding agent solved the task and asks what else it did on the way. The samples span three layers of the action space (code generation, file management, system interaction) and eleven misbehaviors, with a fully automated grader. On OpenHands and smolagents the rates are the story: unintended modification of user inputs in 50.5% of cases, silent compromise of environment integrity in 53%, dependency misinterpretation near the ceiling. The authors then bolt on CODE-KIT, a set of misbehavior-aware guidelines plus a few tools, and cut misbehaviors by 52% on smolagents and 34% on OpenHands while task completion went up rather than down. The result worth keeping is that boundary violations and task success were not in tension; the agents were breaking things they did not need to break.

The same question, asked of agents that talk to other agents, produces a longer list. Salesforce's [A²-Failures](https://arxiv.org/abs/2610.19342) taxonomy from Sarath Shekkizhar, Shafiq Joty and a large team covers agent-to-agent systems where each agent serves a different principal, holds private state the other cannot see, and may be cooperative, mixed-motive, or adversarial. Prior multi-agent failure studies assumed one orchestrator or one shared workspace; this one removes both assumptions and records more than 2,500 runs across 488 scenarios in eight families (legal, CRM, security, commerce and so on), built from several harnesses and models. Out of the traces come 20 failure modes in four buckets: discovery and delegation, grounding and record consistency, verification, and conduct and fidelity. Three findings held everywhere. Agents match tasks to peer names mentioned in the prompt instead of searching for available peers. Agents never fact-check each other unless told to. And scoring only the final output rewards the lead agent while hiding the coordination and verification breakdowns underneath it, which is the argument for scoring each agent against its own objective in addition to the task. The run logs are public on Hugging Face, so the taxonomy is checkable rather than asserted.

If misbehavior is the thing to measure, the next question is whether the text we write to steer agents measurably helps, and Samuele Giampieri's [Cortex](https://ui.adsabs.harvard.edu/abs/2026arXiv261014216G) is the first tool I have seen that refuses to take a harness edit on faith. It treats CLAUDE.md, skills, and path-scoped rules as items to be measured: it saves fixes from developer sessions as replayable tasks, spots recurring corrections, writes one skill or rule at a time, and keeps it only if repeated runs with and without it show a net gain and no single task made noticeably worse. The motivating number is the noise floor. The same harness, measured twice on the same tasks in separate batches, differed by 3.3 points of pass rate with a confidence interval of [−7.3, 0.0], which is exactly the size of effect a developer would call a win after watching it once. On a purpose-built repository under Claude Haiku 4.5, the harnesses Cortex evolved raised convention-following well above a no-rules baseline, left a control area untouched, and added no always-on text beyond a 559-character CLAUDE.md. Delivery mattered more than content: rules, which load automatically when matching files are read, did most of the work; a skill listed on every turn was offered in 198 attempts and opened in none. Two limits the author states plainly: Cortex proved it keeps no unused text, not that it detects harmful text, since the harmful rules landed on tasks that mostly failed without them and the gate reached no verdict; and under Claude Sonnet 5, which already followed the conventions, a single run's harness added little.

Daytona's [sandbox-snapshot study](https://ui.adsabs.harvard.edu/abs/2026arXiv261013841G) from Daniel Thi Graviet and Tanmay Shah is a preregistered negative result with a sharp positive inside it. The idea is Go-Explore for coding agents: snapshot the whole live machine at promising moments, and when a run fails, restore a snapshot and branch a fresh agent from it instead of retrying from scratch. Under a matched budget of one million tokens per seed on five Terminal-Bench 2.0 tasks with Claude Haiku 4.5, independent retry solved 17 of 25 task-seed pairs and snapshot branching solved 6. The failure analysis explains why: budget fragmentation between root and children, restored states that faithfully preserve a wrong partial solution and become sticky, handoff cost (one child burned roughly 190,000 tokens over 26 steps where a fresh retry needed 90,000 over 11), and progress proxies like file edits that are not the verifier. Then they built a task whose progress lives in a SQLite database outside git. From the same planted checkpoint with 200,000 tokens remaining, a clean restart solved 0 of 5, a git-diff restore solved 0 of 5, and a full snapshot solved 4 of 5, using 21k to 41k tokens each. The authors' own framing is the right one: snapshots solve state restoration, not state selection, and they pay off when the work spans services whose state a diff cannot reconstruct.

That boundary, state inside the repository versus state in the running system, is also where durable workflow engines live, and Netflix published the most detailed account of one in years. [Conductor: The Next Chapter](https://netflixtechblog.com/netflix-conductor-the-next-chapter-41ad21067649?source=rss----2615bd06b42e---4), written by Aravindan Ramkumar for the Conductor team, is the answer to what happened after Netflix stopped maintaining the open-source fork. The internal system now backs roughly 200,000 workflow definitions across about 150 applications, executes on the order of 420 million workflows a month, and clears a billion executions roughly every quarter. The 4.0 rewrite separated workflow metadata from per-task records so evaluation loads a blueprint plus the one task it needs, which lifted the per-workflow ceiling from about 2,500 tasks to 30,000 and cut p99 evaluation latency by about 40%. Competing writes to the same task, the classic case being a late heartbeat arriving after a COMPLETED, are resolved without locks by writing terminal states to their own partition and letting terminal win on read, because mixing Cassandra lightweight transactions with ordinary writes had broken consistency. Evaluation moved off the request path onto a Timestone exclusive queue, and failed lock acquisitions dropped from around 2,700 per interval to zero. The parts that matter for agent builders are the newer controls: Run Strategies with a sequence key so executions on the same entity serialize while different entities run in parallel, managed tasks that launch Titus containers or Stratum serverless functions without a polled worker, and a type-safe Java DSL that compiles to the same JSON graph so the live execution view survives. The roadmap names agent tooling, skills, plugins and MCPs, plus a schema registry that blocks non-backward-compatible changes to shared tasks, with an expected 5x load increase next year. The Data Clean Rooms example, multi-day provisioning sequences that yield rather than hold a thread, is the pattern every long-running agent workflow eventually needs.

On the retrieval side, Cognee's [Graph-free Retrieval with Graph-Modified Embeddings](https://arxiv.org/abs/2610.18410) tests whether you can get multi-hop benefit from a knowledge graph without touching the graph at query time. Federica Santi, Vasilije Marković, Daniel Scott and Lazar Obradović compare five offline transformations that fold graph structure into node embeddings, then try different ways of using the modified vectors next to the originals. Replacing the original embeddings outright reduced evidence recovery. Multi-stage strategies that use the graph-modified vectors to steer the search and the originals to score relevance improved recovery by up to 25.9% relative to plain vector retrieval on questions that need linked facts or comparisons among candidates, and matched baseline recovery with 40% fewer returned nodes. Controls separate the graph contribution from the multi-stage retrieval alone. The benchmark is a synthetic professional network with complete supporting-evidence sets, so take the magnitudes as indicative, but the design conclusion travels: how you use graph-modified embeddings matters more than how you produce them.

The semantic-governance hit of the day is an essay rather than a measurement, and it is a good one. Ananth Packkildurai's [The Self-Organizing Data Stack](https://www.dataengineeringweekly.com/p/the-self-organizing-data-stack) in Data Engineering Weekly argues that handing coding agents to data engineers without changing the orchestration model drops the cost of generating a pipeline to near zero while leaving the cost of refactoring one untouched. His alternative starts from intent: a request states only the outcome and commitment, something like create customer_spend_30d, and a planner compiles a formal specification from the semantic layer, meaning authoritative sources, entity keys, units, approved calculations, and temporal rules. The tests derive from the same definitions: one row per customer enforces uniqueness, including zero-spend customers forces an outer join against the customer registry, the approved purchase amount supplies reconciliation against the raw ledger. When a support agent asks for the 90-day version a month later, the engine should recognize the shared definition rather than spin up a duplicate scan of raw purchases, which is what today's copilots do. Every live asset carries a provenance record built on W3C PROV and OpenLineage that references each semantic definition by version, so a defect can name every downstream consumer that read bad data, including agents whose actions a table rollback cannot undo. Two lines to carry around: invest in the semantic layer before the planner, and never let an agent grade its own work.

What to watch: whether SWE-MISBEHAVIOR's automated grader gets run against the closed agents that dominate real usage, whether anyone extends Cortex's gate to detect text that hurts rather than text that is unused, and whether Conductor's sequence-key and schema-registry ideas show up in the agent workflow engines that borrowed its execution model.
