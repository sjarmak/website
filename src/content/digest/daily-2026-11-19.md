In five database incidents whose root cause depended on runtime concurrency, Claude Code announced a cause, shipped a fix, and later walked it back, every time. That is the core observation in [a field report on an agent debugging a production message-dispatch engine](https://arxiv.org/abs/2611.17304) (arXiv, Nov 12), and the authors' diagnosis is more useful than the headline: the agent's wrong hypotheses were consistent with the evidence it could see. It lacked live lock views, untruncated deadlock reports, read-only execution against production, and an explicit statement of which environment it was in. An access gap appeared in all five concurrency incidents, alone in one and paired with a reasoning slip (anchoring on an early cause, misreading transaction semantics) in the other four. The three incidents that did not involve concurrency needed nothing the agent did not already have. Their proposal is a forensics layer inside existing security controls: a safe interrogation API, a lock-and-deadlock flight recorder, and a production replay harness. Anyone wiring an agent into on-call should read this as a spec for the tooling, because each wrong guess cost a full deploy-and-observe cycle.

Google's [AQuA release](https://www.infoq.com/news/2026/11/google-ambient-agent-prod/?utm_campaign=infoq_content&utm_source=infoq&utm_medium=feed&utm_term=global) (InfoQ, Nov 13) attacks the same problem one layer up, for the agents you ship rather than the agents you debug with. The open-source reference implementation reads production agent sessions, confirms that a failure pattern recurs, and then traces root cause against a snapshot of the source that was actually deployed. In a 32-session replay, prompt changes it motivated cut seat-selection bypasses from 15 sessions to two and dietary-preference omissions from seven to zero. Thirty-two sessions is a small replay, but the shape is right: tying a behavioral failure to the exact deployed artifact is what most agent observability stacks still skip.

The multi-agent result of the window is [a break that only appears when a system delegates](https://arxiv.org/abs/2611.17520) (arXiv cs.MA, Nov 12). The authors plant a forged record in a file store and ask Claude Code, Codex, and a reference harness, all unmodified, to answer questions from it. Strong orchestrators searching the store themselves made almost zero harmful revisions across more than 1,000 trials; hand the reading to a cheaper sub-agent, which is what these harnesses are built to do, and the same models on the same facts failed 20/180, 44/180, 75/180 and 553/900 times. In simulations over 18 models, five aggregators that were almost never unsafe alone repeated a corrupted sub-agent's error in 751 of 757 trials. The practical rule follows directly: a delegating system's safety lands near its weakest reader, so model-tier routing is a security decision as much as a cost one.

On evals, [SWE-Bench Pro V2](https://arxiv.org/abs/2610.24206) (arXiv, revised Nov 13) is a maintenance report as much as a benchmark. Agentic audits, expert adjudication and blind re-implementation repaired or retired 480 of 731 tasks, with 23 contracted engineers spending 404 hours, and a second engineer re-solving each revised instruction from the text alone. The hardened protocol restricts network access to the model endpoint and re-grades every patch in a clean container, closing the routes by which agents fetched upstream fixes or got credit for edits outside their patch. The uncomfortable number is that frontier agents now resolve up to 99.4% of the 642 V2 tasks, so the separation lives in a 51-task Hard split that spreads systems from 52.9% to 98.0%.

[An assertion-aware re-score of a multi-agent harness](https://arxiv.org/abs/2606.21666) (arXiv, revised Nov 13) is the most instructive correction in the pool. Its v1 claimed that broadcasting messages between agents raised a hallucination rate from 0.492 to 0.658 and called it contamination; v2 withdraws that. Under a pre-registered plan, three judges from three vendors labeled 1,832 outputs by whether each fact was asserted wrong, attributed to another agent, asserted correct, or absent. On values the agents asserted as their own, the broadcast effect was -0.0208 (95% CI [-0.0458, +0.0041]), indistinguishable from zero; scored by mentions, the judges reproduced the spurious effect at +0.1996. A contradiction judge counts an agent correctly reporting a teammate's error as a hallucination, and any multi-agent eval scored that way is measuring quotation, not belief.

For semantic governance, [MEM-SQL](https://arxiv.org/abs/2611.18338) (arXiv cs.DB, Nov 13) treats an organization's verified query history as a governed asset. Its HARE benchmark builds 1,600 requests from 823 verified queries and annotates which components each request reuses. The system stores whole-query templates, reusable SQL blocks, and mappings from domain concepts to schema elements, consulting the raw schema only when no memory layer matches above threshold. Across six models, execution accuracy rose from 37.1% to 50.0% with 76.6% fewer input tokens and 68.8% lower latency. The failure mode matters more than the average: when a request combines several verified queries, accuracy falls from 56.7% to 29.7%, worst when reused pieces must sit in a new structure or share a join. Reusing approved definitions helps until the agent has to compose them, which is exactly where a semantic layer's join and grain rules would earn their keep.

Two threads to watch. The database-debugging and AQuA papers both converge on giving agents read access to the real deployed state, and the sub-agent paper shows why the reader of that state must be at least as trustworthy as the orchestrator. Whoever ships a forensics API for agents will have to answer both at once.
