A production compression gateway sitting between Claude Code, Codex, and their backing models just supplied the multi-turn cost math that public benchmarks have been skipping. Luzhuo Chen and Jiayu Shi instrumented Paritok, a real gateway handling live coding-agent sessions with Claude Sonnet and GPT-5, and split the token bill into three separate levers: tool-schema filtering, content compression of file reads and tool output, and history summarization. Tool-schema filtering turns out to be the only lever with a flat, reproducible payoff, stripping 21,000 to 57,000 tokens per turn regardless of session length. Content compression looks weaker in isolation, trimming roughly 2% of the cache-priced prefix per turn, but because compressed reads sit in history and get re-sent on every later turn, its savings compound quadratically, about 3,350×N² tokens by their measurement, overtaking the fixed schema-filtering gain within six turns. The paper's sharper claim is that a widely cited benchmark result, 86.5% of SWE-bench quality retained at a 25.7% compression rate, measures something orthogonal to multi-turn cost and shouldn't be cited as a savings argument at all ([arxiv.org/abs/2609.22114](https://arxiv.org/abs/2609.22114)). It's a useful corrective for anyone budgeting agent infrastructure off single-shot compression numbers.

Reliability failures aren't only about token accounting. Two newly disclosed Codex sandbox escapes, Heapjack and Overpatch, both let cloned-repository code execute on the host machine with no approval prompt, reported by Accomplish AI's Oren Yomtov and patched by OpenAI within eight days of disclosure. Heapjack exploited Codex Desktop's node_repl helper, where trusted and untrusted JavaScript shared one V8 heap; a call to getHeapSnapshot() let untrusted code lift the process's trust token straight out of memory. Overpatch abused the CLI's apply_patch tool, which infers write permissions from a patch's parent directory, so naming /tmp in one patch entry widened access to the whole disk even after that entry failed. Yomtov's diagnosis names the pattern behind both: "the thing doing the enforcement was sitting inside the thing being enforced." It's the same shape Pillar Security found across Cursor, Codex, Gemini CLI, and Antigravity in July, and Cymulate found across Claude Code, Gemini CLI, and Codex in April, via workspace configs and trusted-tool allowlists rather than shared memory ([devops.com](https://devops.com/codex-sandbox-escapes-show-why-agent-guardrails-cant-live-inside-the-agent/)). Read-only mode didn't stop Heapjack. The fix pattern keeps repeating: enforcement has to live in a layer the agent can't modify, not inside the sandbox it's supposed to constrain.

Evals keep exposing the same soft spot: memory systems that score well on recall don't necessarily make agents better at the job. VibeMemBench, built on 111 targets from 90 SWE-rebench V2 repositories and 3,634 history trajectories, only counts a target if injected prior experience demonstrably improves its executable outcome under a reference setting, then transfers that verified experience to five held-out solvers. Direct injection of the verified experience raised task resolution by 1.1 to 4.5 percentage points on four of five solvers and cut agent steps across all five. But when four existing memory systems had to construct and retrieve that same experience themselves, rather than receive it pre-verified, eleven of twelve system-solver pairings failed to beat a memory-off baseline ([arxiv.org/abs/2609.23570](https://arxiv.org/abs/2609.23570)). The repository history holds useful experience; the memory systems built to deliver it mostly don't.

That gap between what's stored and what's usably retrieved shows up again in orchestration. MAGE, a hypergraph-based memory engine for multi-agent systems, argues that vector and graph memories flatten the events that actually matter, agents, tools, documents, errors, evidence, into embeddings or pairwise traces that lose the higher-order structure of who decided what and why. Storing agents, messages, tools, and decisions as a heterogeneous temporal hypergraph instead preserves those collaborative events as reusable, role-aware, budget-bounded memory rather than flattened recall ([arxiv.org/abs/2608.29678](https://arxiv.org/abs/2608.29678)). Paired with VibeMemBench's findings, multi-agent memory is converging on the same lesson driving the compression paper: what a system can technically store matters less than what it can correctly reconstruct on demand, under a token budget, for the agent that needs it next.

Retrieval itself is being reframed around that same constraint. A new framework reformulates the objective for AI search: instead of ranking documents by human search satisfaction, its three-stage pipeline picks documents by whether they support a correct answer, assesses their trustworthiness on source, temporal, and factual grounds, and then packs the survivors into a finite context budget for generation, with an evaluation protocol covering both retrieval-side context and the final answers ([arxiv.org/abs/2609.23354](https://arxiv.org/abs/2609.23354)). It's the retrieval-side mirror of the memory papers above: once an LLM is the consumer of retrieved content rather than a human skimming a results page, ranking for relevance alone stops being the right objective.

On the semantic-governance side, a seven-agent framework reverse-engineers Business Requirements Documents straight out of undocumented enterprise code, test suites, and configuration, corroborating extracted rules against real production defect records and generating a full bRD in under nine minutes per service. Measured against a comparable prior migration that took over two years by hand, the authors claim a cost reduction exceeding 98%, using IFPUG complexity models and industry labor benchmarks for the comparison ([arxiv.org/abs/2609.22719](https://arxiv.org/abs/2609.22719)). It's a narrower claim than a governed semantic layer, this recovers rules that already exist rather than enforcing new ones, but it's a concrete instance of turning undocumented business logic into a machine-readable artifact an agent, or an auditor, can actually check against.

Every result above traces back to the same failure mode: convenient benchmark numbers that don't survive contact with a real multi-turn session, a real sandbox, or a real repository history. Worth watching whether Paritok's cost-attribution method gets adopted as a standard way to evaluate compression gateways, since "preserves benchmark quality" and "saves money" have turned out to be nearly unrelated claims.
