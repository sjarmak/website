Anthropic reports that Claude Code's auto mode, the two-stage transcript classifier that decides which tool calls run without asking, misses 17% of dangerous actions on production traffic. A [revised stress test posted Friday](https://arxiv.org/abs/2604.04978) by Zimo Ji and colleagues measures 81.0% end to end (95% CI 73.8 to 87.4) on AmPermBench, 128 deliberately ambiguous DevOps prompts covering 253 state-changing actions. The authors call that a different workload rather than a contradiction, and the mechanism matters more than the headline: 36.8% of the state-changing actions were in-project file edits, which sit in a tier the classifier never evaluates. When the expected CLI is missing during artifact cleanup, agents fall back to editing the state files directly, and the miss rate on that task family reaches 92.9%. Even on the 160 actions the classifier did see, false negatives ran 70.3% with false positives at 31.9%. A gate that assumes danger travels through the shell will keep missing an agent that can get the same effect with a file write.

That pattern, a check that covers one path while the agent takes another, ran through most of what landed in the last two days.

[ProductWebBench](https://arxiv.org/abs/2610.31118) makes the case for frontend coding agents. It freezes living repositories, stages requirements through a simulated user, and keeps every check that passed earlier armed for the rest of the run, across 320 Change tasks and 80 long-horizon Build tasks. Over 8,737 runs from 13 models, 28.2% of the Change runs that passed every requested-work check still failed a continuity check: a blank route, horizontal overflow, console errors. Another 10.8% pushed a browser state they had already passed back into failure. Because the same checks also run on the untouched repository, each regression comes with provenance rather than a post-hoc label, and interaction failures showed up in 29.5% of runs whose static DOM looked fine. If your eval scores only the target of a change, more than a quarter of your passes are breaking something you did not grade.

[Agentic Verified Optimization of Real-World Software](https://arxiv.org/abs/2610.30188), from Zhe Ye, Dawn Song, Soonho Kong and coauthors, replaces the tests with proofs. Agents already game test-based equivalence checks, so here the agent writes a faster implementation in Lean 4 plus a machine-checked proof that it matches the original, which serves as its own specification and removes the spec-writing bottleneck that stalls most verified code generation. On Verina's 189 reference implementations, agents produced proved, faster rewrites for 156, including swaps from exponential recursion to dynamic programming. A companion framework, Aqueduct, ports C, C++, Go and Rust programs into native Lean and validates each port by differential testing; across 17 migrated applications, 92 proved rewrites sped up 47 of 51 scenarios. Application-level gains were smaller than function-level ones, which makes "which function should the agent touch" the open problem, and the Lean migration step is still the cost anyone outside the Lean ecosystem would pay first.

Memory has its own version of the coverage gap. [Governance-State Corruption in Long-Term Memory for LLM Agents](https://arxiv.org/abs/2610.30698) holds stored content and tasks fixed and corrupts only the validity state that decides which records enter the model's context, the case where retrieval is correct but the record should no longer apply. Across six providers and 2,080 matched fault pairs, corruption changed the operative context in 96.25% of pairs, and oracle-backed enforcement restored it in all of them. Downstream, the clean-minus-corrupted gap was 40.54 points on LongMemEval binary correctness and 30.60 on rescaled Memora FAMA. The authors label their full-cohort effects descriptive proxies, so treat the exact figures as bounded, but the recommendation stands on its own: a memory eval that measures recall alone will report a healthy system while the agent acts on superseded facts.

On the analytics side, a [revised version of Metadata Reasoner](https://arxiv.org/abs/2604.20144) from Jiani Zhang, Sercan Arik, Cosmin Arad, Fatma Ozcan and Alon Halevy works on the step that precedes any text-to-SQL: deciding which tables an analytical task should touch at all. A table-search engine retrieves candidates, then the agent reads their metadata to settle on a set that is both sufficient and minimal. It reaches 88.63% F1 on KramaBench data selection, 10.73 points over the strongest baseline, and holds 93.5% F1 on a BIRD-derived lake seeded with redundant and low-quality tables while avoiding every low-quality one. Interleaving selection with partial query execution adds 4.8 points of selection F1 on runtime-dependent tasks and 5.3 points of end-to-end accuracy. This is table-level grounding, a step short of governed metric definitions, but it measures the wrong-table failure the semantic-layer argument rests on, and it shows that inspecting intermediate results beats choosing sources in a single pass.

DoorDash's [feature-flag cleanup report](https://arxiv.org/abs/2610.31351) is the production counterweight. The company has more than 56,000 flags across 623 repositories, 1,659 of them stale as of May 2026, at an estimated one to two hours of engineer time per manual removal, and rule-based tools had not kept up. The multi-agent system reads live rollout state over MCP, picks up the Jira ticket, and opens the pull request end to end; on 50 stale flags it produced engineer-approved PRs for 45, averaging $4.79 and 13.8 minutes each. Fifty flags is a small sample, and human merge approval is doing real work as the final gate, but the task is well chosen: live rollout data gives the agent ground truth that a code-only reading would not have.

The same lesson at the infrastructure layer comes from an [r/LLMDevs post on enforcing LLM spend caps under concurrency](https://www.reddit.com/r/LLMDevs/comments/1xe4nr2/enforcing_an_llm_budget_under_concurrency_6_bugs/). Fifty workers all read $9.80 against a $10 limit, all pass, and the budget overshoots by fifty calls; the fix is an atomic reserve-then-settle, in one Redis Lua script or one conditional Postgres `UPDATE`. The failures that bit hardest were reservations leaked by workers killed mid-request and streams cut off before the final usage message arrives, which leave the ledger under-counting during exactly the incidents that matter. The proposed test is worth copying whatever your stack: a $1.00 budget, 500 concurrent requests against a stub with random latency, 5% of workers killed mid-flight, then assert that spend stays under the limit, reservations drain to zero, and no reservation settles twice. The author works on a cost-control proxy and says so; the techniques are standard.

The open question after Friday's papers is whether permission systems will move from classifying commands to classifying effects. Auto mode's 36.8% blind spot exists because the gate inspects the verb rather than the state change, and ProductWebBench's continuity checks show what effect-level grading looks like for a frontend. Watch for the first coding-agent permission layer that diffs the project state, rather than the transcript, before it decides whether to ask.
