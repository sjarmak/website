Keeping only the last five observations in a coding agent's history cut its prompt volume by 33.3% and raised its uncached prefill by 608.5%. That result comes from [The Physical Cost of Context](https://arxiv.org/abs/2610.34763), announced today, and it goes after the number most context-management work reports: prompt tokens saved. Under a caching runtime the model prefills only the tokens after the longest cached prefix, so a policy that rewrites earlier history throws away reuse the runtime had already paid for. The authors split executed prefill into logical prompt minus reused prefix and measure KV residency, wall time, and a GPU-energy proxy, all behind a five-point non-inferiority gate on quality. On 450 localization cases derived from SWE-rebench V2, preloading ten retrieved blocks up front (Eager) and adding anchored history compaction on top (Compact) both pass the gate. In a separate 900-cell study, Eager cuts model calls by 35.7% and the energy proxy by 33.2% against on-demand grep search, and Compact saves nothing further. Turning on prefix caching leaves Eager's prompt volume about where it was (+8.3%, with a 95% interval spanning zero) while cutting its uncached prefill by 67.7%. The keep-five policy, which the authors call Mask-5, ran with mini-SWE-agent on 100 SWE-bench Verified instances and discarded 135.9k reusable tokens per task; that is where the 608.5% comes from, and the energy proxy rose 125.6% while the run missed the quality gate. Context policies save physical work by shortening the trajectory, and they multiply it by editing history the cache could have reused. A compaction scheme that reports only token counts is reporting the wrong ledger.

[How Do Small Coding Agents Use Code Graphs and Embeddings?](https://arxiv.org/abs/2610.33958) tests the premise behind every code-intelligence tool handed to an agent, that the repository's structure is something the model lacks and the tool supplies. Saurav Bellam stratifies SWE-bench Verified by hop depth, the shortest code-graph path from code the issue mentions to code the gold patch changes, and ablates a localization agent's tools (grep only, plus embedding search, plus graph tools, all three) across ten open-weight models: six Qwen3 sizes from 0.6B to 32B, an FP8 control, and three Gemma 4 sizes, 79k episodes in total. Structured tools double grep-only accuracy for Qwen3-8B and Gemma 4 E4B. The gain peaks at 17 to 21 points between 1.7B and 4B parameters and shrinks to 4 or 5 points at 32B, an odds ratio of 0.77 to 0.82 per doubling of size. From 8B up, about half the gain comes from the form of the submission rather than from finding the target, and the drop between 14B and 32B is a drop in tool uptake at equal grep-only accuracy. Each extra hop multiplies the odds of correct localization by 0.50 to 0.67 at every size, and no tool set flattens that slope. The traces explain why: graph tools help through name lookup at hop 0 and a single expansion at hop 1, and agents chain expansions in only 12 to 14% of episodes. A fixed repair model turns these localizations into 6 to 13 resolved tasks out of 160, against 26 from oracle localization. Linear probes find direct call edges decodable at AUC 0.74, below a lexical baseline at 0.99, with two-hop edges at 0.57. Small agents hold a one-hop, mostly lexical picture of the repository, in their weights and in how they use tools. For anyone building graph tooling, multi-hop traversal offered as a tool goes unused, so the traversal probably has to happen on the tool side and come back as an answer.

A root-cause-analysis study reaches a related conclusion about scaffolding. [Free to Look, Free to Reason](https://arxiv.org/abs/2610.35767) compares three harnesses that prescribe none of the model's calls (a single call over an evidence package, a SQL agent, and the Codex coding agent) against five published LLM root-cause-analysis agents and a set of statistical and causal methods. The benchmark, RCAtlas, holds 90 validated microservice-failure cases from eight public datasets, run across six models and three reasoning efforts. The simple harnesses score 65 to 77% precision-at-1 on three mid-tier models; the published agents score 16 to 53%, and the non-LLM methods 6 to 39%. The published agents hard-code anywhere from a tenth to all of their model calls in program logic, and a case study shows those prescribed procedures skipping the evidence that decides the case. A stronger model mostly buys reliability, a multi-turn harness mostly buys aptitude, and raising reasoning effort moves accuracy a few points while multiplying wall time by up to seven. Among runs that beat the best non-LLM method, every Pareto-optimal run on cost or time used a simple harness. Set next to the code-graph result, the pattern is that scaffolding helps when it hands the model information and hurts when it decides for the model where to look.

Security review got a benchmark built from the right end of the history. [SecPRBench](https://arxiv.org/abs/2610.33509) harvests real bug-introducing commits instead of reconstructing the reviewed change from a later fix, then builds and validates each one; it currently holds 265 tasks from nine systems including Firefox, V8, and OpenSSL. Across eight frontier models, recall runs from 32.5% to 78.1%, with Grok 4.6 and GPT-6 sol at the top. The failure analysis is the part to keep: in 68% of misses the agent reports on the file that holds the flaw and argues for a different mechanism. A human reading that report is pointed at the right file with the wrong story, which is a different risk from silence, since the story can end the search. Security-specific harnesses move recall in both directions; OpenAI's Codex Security lowers it by 8.3 points, mostly by abstaining, and Anthropic's Defending Code harness raises it by 7.7 points at higher cost.

On orchestration, [Understanding Communication Failures in Multi-Agent LLM Systems](https://arxiv.org/abs/2610.32060) builds a taxonomy from 3,211 failed multi-round trajectories spanning medical QA, coding, finance, multi-hop reasoning, ethics, and embodied text tasks. Most failures are recovery or consensus problems rather than isolated first-round mistakes, and many appear only after agents first see their peers' answers: agents converge too early, ignore dissent, suppress a correct minority answer, or carry a wrong framing across rounds. The authors' recommendations follow from that distribution, namely explicit disagreement handling, evidence verification, preserving minority signals, and a recovery check before the system finalizes. For debate-style designs, the round where agents first read each other is where instrumentation belongs.

The governance item is a leaderboard entry with a permission boundary built in. A post on [r/LLMDevs](https://www.reddit.com/r/LLMDevs/comments/1xfktk2/opensource_schema_selection_claude_opus_55_is_now/) reports that schemagate, an open-source schema-selection layer, paired with Claude Opus 5.5 took first place on the BIRD Mini-Dev text-to-SQL leaderboard after the BIRD team merged the entry: 81.00 execution accuracy on SQLite, 72.40 on MySQL, and 72.60 on PostgreSQL over the 500 questions, scored with BIRD's own evaluator, with the same layer plus Gemini 2.5 Flash in second. It makes one Claude call per question. The layer selects only the tables and columns the question needs and that the caller is allowed to read, then checks the generated SQL against that selection before it executes, and the author published code, predictions, and scorer logs. Putting schema linking and access policy in the same component is the right shape for governed execution. BIRD scores execution accuracy only, though, so the half of the layer that enforces read permissions goes unmeasured here, and Mini-Dev's public databases carry none of the governed metric definitions, grain rules, or conflicting business terms that make enterprise schemas hard.

What to watch: whether coding-agent vendors start publishing uncached prefill alongside token savings, whether code-graph tools move multi-hop traversal server-side now that small agents have been shown not to chain it themselves, and whether any text-to-SQL benchmark begins scoring policy violations next to accuracy.
