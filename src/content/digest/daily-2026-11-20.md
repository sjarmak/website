Seven identical runs of the same untuned finance agent, on the same 18 questions, passed anywhere from 105 to 123 of 149 rubric criteria, and the bill moved by up to 17% between them. That spread comes from [Can You Trust Your Finance Agent?](https://arxiv.org/abs/2611.17939) (arXiv, November 16), a case study on the reference agent shipped with the Vals Finance Agent Benchmark v2, and it sets the floor for every other claim in this issue: if you have not measured your agent's run-to-run noise, you do not know whether any change you made did anything.

The authors build everything on that floor. They classify 20 failed trajectories by which owner would have to fix them, under a taxonomy frozen before they looked: 13 belong to the agent's instructions, 3 to its tools, 4 to the model, and none to its data. Four blind readers from three model families agree with their LLM analyzer 94% of the time, which matches the 93% rate at which the readers agree with each other. Then comes the useful part. An optimization loop making one targeted change per round cut cost to 0.34x baseline on held-out questions (95% CI 0.22 to 0.58) at accuracy within noise, while an accuracy-objective run gained 14 points on development questions and 1.5 on held-out ones, with a confidence interval of -5.3 to +7.2. Judged against noise measured first, under a decision rule written before the test set opened, the cost saving is real and the accuracy gain is not. It is one agent and nine test questions, and the paper says so, but the method transfers.

Pinterest arrived at the same discipline from the production side. Their [Analytics Agent compliance writeup](https://medium.com/pinterest-engineering/how-pinterest-improved-analytics-agent-compliance-with-loop-engineering-d3c52d0abaa2?source=rss-ef81ef829bcb------2) (November 12) is the most direct governed-analytics item in the feed: "compliance" means the agent inspects table metadata before writing SQL, reads the data-discovery skill when it needs to, and searches certified metrics and dashboards instead of stopping at the first table it finds, because skipping those steps is how an agent confidently reports a number computed against the wrong definition or reporting window. Manual prompt revision topped out at 64% compliance on one rule. Their fix is a tuning loop with paired suites per rule (a "required" suite and a "skip" suite, so "always search dashboards" cannot score perfectly by over-firing), a regression suite that blocks any change hurting unrelated behavior, and a fresh-context session each iteration that reads a structured handoff of scores, failing cases, rejected approaches, and edit budgets. The finding that matters most sits in the measurement section: their first big run hit 89.3%, but rerunning identical code flipped 10.3% of 223 case verdicts, and iterations 21 through 30 added nothing. Pinterest ran a single model at one reasoning setting with an uncalibrated LLM labeler, and the footnotes are candid about all of it.

The enterprise-analytics angle gets a controlled comparison in [Comparative Analysis of Agent Evaluation Frameworks](https://ui.adsabs.harvard.edu/abs/2026arXiv261114493Z), which pits trace-based LLM judging, text-only LLM judging with red-teaming, and deterministic heuristics against two analytics agents on frozen traces. On 72 ground-truth cases the trace-based judge reaches F1 0.90; the text-only judge matches its recall but raises 5x more false alarms. An unknown-risk phase surfaced 24 new failures with zero overlap between functional testing and security red-teaming, which argues for running both rather than picking one. The core finding is plain and worth repeating to anyone shopping for an eval vendor: what the judge can see decides how good the judge is.

[Repairs for Whom?](https://arxiv.org/abs/2610.38610) (revised November 13) pushes the "who is evaluating" question into agent self-repair. Holding failed trajectories and candidate single-step repairs fixed, the authors label each repair by rolling out the deployed policy itself, then measure what other evaluators lose. Greedy replay forfeits 0.08 to 0.13 of net success gain on ALFWorld. Twenty Qwen2.5-14B rollouts per candidate are worth no more than two of the 7B agent's own, and the agent's own fine-tuned successor is worse still, losing 0.55 to 0.60. Across settings, substitute evaluators forgo 11% to 53% of the value of selection. If your repair or self-improvement pipeline scores fixes with a bigger model or a judge reading the log, those labels describe a different agent than the one that will execute them; the authors recommend tagging every repair label with its executor and training version.

On the coding side, [Will It Survive?](https://arxiv.org/abs/2601.16809) (v2, November 13) runs a survival analysis over 648,959 lines from 2,794 merged PRs across 215 repositories in the AIDev dataset. Agent-attributed code is not modified sooner than human code in the same repos; weighted per PR it is modified later (hazard ratio 0.83), driven by Copilot and Codex (0.76), while Devin matches humans (0.95) over the full period. The effect disappears without PR weighting, and when agent code does change, the intent mix looks like human changes (Cramér's V 0.080). File size and recent churn predict modification better than the code tokens do (AUC 0.78 vs 0.70). The "agent code is disposable" story does not hold up on this data, though the per-PR weighting choice carries the headline.

[AgentRoom](https://arxiv.org/abs/2608.23740) (v2, November 13) gives concurrent coding agents a CRDT-merged shared filesystem with file-level claim, status, and broadcast exposed as MCP tools. Across five frontier coding CLIs on four backend tasks, two coordinated agents abandon fewer tasks than a solo agent (which stubs out one file and exits on up to half of hard tasks) and vary less run to run. The ablation is the takeaway: coordination primitives, not parallelism or the CRDT merge itself, carry the gain. The evidence is ordinal and judge-based, so treat the direction as more reliable than any magnitude.

Pinterest's 10% verdict flip rate and the finance paper's 105-to-123 spread are both single-system numbers. The open question is whether anyone will publish noise floors across agents and models as a standard benchmark column, next to the score it qualifies.
