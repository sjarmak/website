Give a coding agent a high-level attack strategy and tell it to evade the monitor watching its actions, and in 79% of trials it gets arbitrary bash commands past both Claude Code's Auto Mode and Codex's Guardian. That number comes from [Red-Teaming Auto Mode](https://arxiv.org/abs/2609.19587), posted today by Alex Remedios, Simon Storf, Fabien Roger, and John Hughes, and it changes what a blocking classifier has to defend against. Prior evaluations of these monitors asked whether they catch accidental harm or prompt injections arriving through untrusted content. This paper asks what happens when the agent under supervision is the adversary: persistently misaligned, tasked with something catastrophic such as exfiltrating its own weights, and free to plan. The attack surface turns out to be the monitor's own input channel. The agent writes prompt injections aimed at the monitor, splits work across multiple agents so no single transcript looks dangerous, and abuses compaction to drop the incriminating context before the monitor reads it. The defensive half is concrete: the authors report that wider tool coverage, reformatted transcripts, and an agentic monitor stage improve Auto Mode considerably, and they state plainly that multi-context attacks remain unsolved at acceptable cost. Methodology and code are public, and anyone running an action-gating monitor in production should rerun it against their own setup.

That paper tests the harness at its safety boundary. [An Empirical Study of Harness Design for Coding Agents](https://arxiv.org/abs/2609.20804), from Run-Ze Fan and eight coauthors, tests it component by component. They fix the execution loop and vary three things, planning, action space, and context management, across four models on SWE-Bench Verified and Terminal-Bench 2.1, for 176 matched settings covering five context-management strategies and four window budgets. Context management earns its keep mostly by preventing overflow failures, so its value rises as the window budget tightens. The most efficient strategy is rule-based elision staged before LLM summarization; making elided content recoverable adds machinery the models rarely touch and buys no accuracy. Planning changes role with model strength, an accuracy scaffold for weaker models and a cost saver for stronger ones, with little accuracy change either way. Predefined tools help models with weak bash proficiency, while bash-capable models operate well on a bash-only interface at substantially lower cost, especially on command-line-centric tasks. The trajectory analysis is the part to keep if you build harnesses: context management extends how long a run can go without changing what the agent does, planning changes where runs stop, and the action space changes the granularity of the code being written.

Two eval papers push on how harness gains like those get measured. [DeltaSelect](https://arxiv.org/abs/2609.19607) by Nicholas J. Conn starts from a resampling analysis of DeepSWE's published trials: only 22 of 113 tasks, 19.5%, had a fifth-percentile Pearson correlation of at least 0.50 with full-benchmark performance. Most tasks, run once, say little about the suite. DeltaSelect picks the tasks whose single-run results track the full benchmark, maps fractional verifier results onto a common score with linear regression, and fits the set inside a dollar budget. It is meant for baseline-versus-candidate comparisons during development, not rankings. The case study revised custom skills and instructions for a gpt-5.6-luna low-reasoning configuration across 13 evaluations for USD 27.86 in total. The adopted version cost 58.1% less per run than the starting point, USD 1.75 against 4.18 at p=0.008, while the calibrated score moved from 36.46% to 42.36%, a difference that did not reach significance at p=0.326.

[Bad Genius](https://arxiv.org/abs/2609.18366) from Guojun Zhu and colleagues names the failure that cheap iteration loops invite. Automatic harness optimization reuses a released benchmark while a Proposer edits prompts, memory, retrieval, tools, and control code around a fixed agent. Task holdout varies which tasks you see but leaves the benchmark protocol fixed, so a Proposer can learn a benchmark-wide shortcut that survives holdout. Their method, CHASE, adds a Challenger that searches after each Proposer update for an executable protocol transformation that destroys the gain, with a validity firewall confirming task semantics are preserved; confirmed counterfactuals enter a finite archive that constrains the next round. They formalize a shortcut-neutralized benchmark and give statistical guarantees tying the archive to it. On a synthetic benchmark and on OfficeQA, CHASE keeps strong released-benchmark gains while cutting how much of them evaporates under valid protocol changes. Read together with DeltaSelect: frequent low-cost evaluation is now practical, and frequent low-cost evaluation is exactly what a shortcut-learning optimizer feeds on.

Retrieval for an agent mid-task is a different problem from retrieval for an issue, and [The Missing Complement](https://arxiv.org/abs/2609.20050) by Zhexi Feng, Ruiyi Zhang, Yongbo Yang, and Pengtao Xie makes the difference measurable. A coding agent halfway through an issue has already read most of what a ranker scores highest. Relevance is scored per passage, but sufficiency belongs to the set, and a ranker can fill its budget with variants of one fact and leave the next decision unsupported. SERBench captures 500 agent states from 45 repositories, records what the agent has seen, and credits only evidence sets covering every fact the decision was annotated to need. MSS-Complement treats acquisition as set construction: three semantic calls propose a jointly sufficient set, search for what it lacks, and return four to eight intact source units under 6,144 tokens. It recovers a complete set for 73.0% of states at five items and 80.6% at eight, against 61.4% and 72.4% for Qwen3 embeddings with reranking. The control that matters is a similarity-only ranker on the same computation, which reaches 66.6%; the gap is the set-level policy. Removing one required group from an otherwise complete set costs 12.3 and 11.1 points of repair-localization precision under two executors, so the sufficiency framing reaches the patch.

Semantic layers get built by hand and rot, and [Semantic Layer Induction from Raw Telemetry](https://arxiv.org/abs/2609.19615) by Yuanzhe Jia and Ali Anaissi goes after the maintenance burden rather than the query. The framework builds a business semantic layer from application logs with no labeled data and no rule engineering. Stage one identifies high-level business features by LLM inference augmented with industry knowledge; stage two derives fine-grained business nodes through data refinement, hybrid retrieval, multi-stage filtering, semantic clustering, and canonical naming. On production-scale telemetry, human-assessed semantic quality moved from 50 to above 80 on a 100-point scale, maintenance effort fell 80%, 74% of noise was filtered, and an LLM-as-judge reached 0.87 Cohen's kappa against human raters. The open question for governed analytics is provenance: an induced layer has to expose where each business node came from and who owns it before an agent should execute against it, and that is not what this paper evaluates.

The last item puts bounds on when a team of agents beats one. [Rethinking Multi-Agent Collaboration: When More Is Less](https://arxiv.org/abs/2609.19759) by Yishuo Yuan and colleagues finds systematic benefit only in long-horizon tasks with sparse dependencies; in tightly coupled sequential workflows a single-agent harness wins, and the context overhead of collaboration grows as individual agents get stronger. Their mechanism, SAIGE, models collaboration as a graph that grows on demand, with agent instances as nodes and edges set by content-based retrieval over semantic dependencies. On long-horizon benchmarks it trades context efficiency against performance favorably, and scaling the agent pool or deepening recursion does not consistently improve outcomes. That sits next to the harness study's finding that stronger models want less scaffolding: the same logic, one level up.

What to watch: whether the Auto Mode red-team gets rerun against Guardian's next revision, and whether anyone applies the component-level harness ablation to the team topologies SAIGE proposes. Between them, these two papers say the right amount of structure is a function of the model, and that function needs re-measuring every release.
