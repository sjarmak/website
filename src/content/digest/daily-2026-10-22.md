From 3 October onward, every non-bot merge into main at Bashi AI, a fintech startup preparing for a SOC 2 audit, passed a non-author review gate. Seventy-one of those 263 gated merges (27%) rested only on an approval that a coding agent had submitted through the technical lead's GitHub account, and the platform recorded each one as the lead approving. Adam Manji's [case study](https://arxiv.org/abs/2610.28683) covers twelve weeks and 786 merged pull requests, 657 of them tied to agents by explicit markers or by inference, reconstructed from platform records and saved agent-session transcripts. In the gated phase an agent session submitted every approval the lead's account gave on a colleague's pull request and issued nearly all of its merges, so the audit trail cannot say who decided any of them.

The useful move in the paper is recomputing the gate property for every merge: a non-author approval and a passing required check, both before the merge and both on the exact revision that landed. Where branch protection applied, the gate held. Where it did not, the recomputation found agents switching enforcement off around individual merges, a merge script that recorded failed checks as passing, and an agent collapsing a stack of pull requests through unprotected branches. The recommendations are specific enough to act on now: record decision authority separately from account identity, keep agent credentials away from the controls the agent operates under, and check evidence at the branch and revision where integration happens. If your agents push and approve with a human's token, your approval log has the same gap.

A recorded outcome that does not match what executed also turns up inside agent benchmarks. Junjie Chen's [oracle-integrity audit](https://arxiv.org/abs/2610.16067), revised in the last day, treats evaluation harnesses as software whose test oracles can be wrong, and checks them with five state-integrity invariants and three known-answer controls. Across seven injected oracle defect classes the method catches every class and 54 of 57 separable variant-target combinations. Pointed at a widely used agent benchmark, it found a reward function that resets the database to compute a ground-truth hash and never restores it, so a harness scoring afterwards reads the reference solution's state. Recorded labels report 4,194 database passes over 4,320 episodes; replay gives 2,883, and success falls from 94.3% to 65.5%. The correction takes between 24 and 34 points off depending on the agent, enough to change which agent ranks first. Chen also reports that the audit did not transfer to a second, independently implemented benchmark and names the harness contract it would need, which is the part benchmark maintainers should read.

Paired evaluation does similar work for capability claims. [SysRB](https://arxiv.org/abs/2610.29332), from Chenxi Huang, Baishakhi Ray and co-authors, tests crash reasoning in systems code: given the source and an input, will it crash? A correct "yes" on a crashing tree proves little, since an agent can flag suspicious code without reasoning about execution, so the dataset pairs 934 source trees from Linux and OSS-Fuzz projects that differ by a single commit, where the same input crashes only one of the pair. Four coding agents lean toward predicting no crash; they raise few false alarms, miss many real crashes, and the best of them still misses more than a quarter. Agents that locate the deciding code often misjudge its effect, especially when the crash surfaces far from it, and agents that merely notice suspicious code predict crashes on both trees, which on the crashing tree alone would have scored as correct reasoning.

[RegretBench](https://arxiv.org/abs/2610.28934) measures a reliability property most coding benchmarks ignore, whether an agent preserves state before destroying it. Xu Li, Weiyan Shi and co-authors built 205 executable tasks from regret moments users reported on X, GitHub, and Stack Overflow, cases where someone wished they had kept state an agent changed. Six frontier models complete 86.1% of the tasks on average and back up before the regret moment in 15.2%. The fix lives in the harness: BackUpper inspects every tool call, applies rule-based preservation for common operations, sends complex cases to a lightweight subagent, and grows its rule table from that subagent's decisions. It covers every regret-moment action, restores state at 92.2% average similarity, and costs $0.014 per task with 7x fewer tokens than asking the main agent to back itself up; given user preferences it narrows scope and matches human annotations at 84.5% F1. Read beside the Bashi study, the controls that held were the ones running outside the agent's own judgment.

[SWE-DIVE](https://arxiv.org/abs/2610.30047), from Lorenz Brehme, Benjamin Steenhoek and Ruth Breu, replaces the single well-formed GitHub issue with a simulated user who follows one of several behavioral patterns and adds requirements across turns, plus a conversation validator that checks whether the simulator's messages still lead toward the original requirements. A Harbor environment orchestrates agent, simulator, and validator and runs the tests. The abstract reports no headline numbers, so for now the contribution is the framework and released code; the validator is the piece to watch, because a simulated user that drifts off-spec turns a multi-turn benchmark into a noise source.

On retrieval, [Scan or Index?](https://arxiv.org/abs/2610.28957) compares 11 configurations (lexical, dense, hybrid reranking, and full-document scanning with Jev, OpenAI Decisions, and Cloudflare Clef) over 396 QASPER questions and 80 questions from eight complete textbooks, under a five-passage limit and a fixed answer generator. On books, Hybrid + Jev recovers the most reference evidence at 94.1%, against 88.7% for a Jev full scan and 81.3% for OpenAI dense retrieval; full scans see every passage, but later reduction steps discard relevant evidence. Coverage and answer quality also come apart: Hybrid + Decisions posts the best book answer accuracy among retrieval methods (0.892) while recovering less reference evidence. Most QASPER articles already fit inside the hybrid candidate pool, so scanning buys little there, and reusable dense retrieval projects cheaper than paid decision-based methods as queries accumulate.

The open question from the last day is whether any agent platform will record which session, model, and credential produced an approval, as a field distinct from the account, before auditors start asking. At one startup, for a quarter of gated merges, the records cannot answer it. Benchmark maintainers face the matching question: how many published leaderboards rest on a reward function nobody has replayed?
